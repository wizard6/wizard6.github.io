progressive-build SKILL

Demo-first · 三步顺序 · 硬门禁

← 工作台 SKILL.md GitHub

三步顺序（必须按序）

  1. 简单架构设计 — 填上模型不管的缺口，尤其是落地形式
  2. 可运行竖切骨架 + 增量交付 — Walking Skeleton + Incremental，每片确认再往下
  3. 演化式迭代 — Evolutionary Iterative，按反馈长产品（螺旋仅高风险可选）

一口气做完整实现 = 反模式。

Step 1 · 简单架构设计

过程模型不规定落地形式。缺省时当成缺口；填完（或接受默认）再进 Step 2。

落地形式缺口表

缺口要定什么
Host本机 / 助手机 / Pages / Docker / 其他
Runtime静态文件 / 本地服务 / 容器 / 桌面
Entry打开演示的 URL / 路径 / 命令
Repo / folder本轮源码位置
Data locus磁盘 md / localStorage / 远端 / 仅 stub
Stack bounds例如只要 TS+HTML
Auth / network仅 localhost / 局域网 / 公网（演示偏安全）

骨架级架构只要：一句话系统形状、Slice 0 幸福路径、明确推迟项。不是完整设计文档。

Step 2 · 可运行竖切骨架 + 增量交付

Walking Skeleton：一条真正能跑的端到端细线（UI → 逻辑 → 存取/stub），跑在 Step 1 的落地形式上。

Incremental：骨架通过后，每次只加一个能力；始终可运行；每片硬门禁。

每片汇报

  1. Open（Entry）
  2. 落地形式（Host + Runtime）
  3. Works
  4. Not yet
  5. Propose next

Step 3 · 演化式迭代

每一轮：意图 →（必要时重做 Step 1）→ 可运行结果 → Step 2 切片 → 你确认 → 再进入下一轮。

只规划本轮骨架 + 接下来 2–4 个增量片；更远的迭代用一句话占位，不排成执行计划。

何时用 / 何时跳过

用：新项目、大功能、会改用户可见行为的重构。

跳过：一行修复、纯问答、配置开关，或你明确说「一口气做完」。
