progressive-build SKILL

模块演示页 · 约 80% · 再下一个

← 工作台 SKILL.md GitHub

一句话意思

做一个软件拆解成多个模块；给每个模块做好一个演示页面；做到大约 80% 之后再开发下一个。

工作单元是模块；验收物是可打开的演示页；模块之间有硬门禁。

三步顺序

  1. 简单架构设计 — 落地形式 + 薄架构 + 模块地图（顺序、每模块 Demo Entry、80% 验收点）
  2. 按模块：演示页 → ~80% — 一次只做一个模块；先演示页，补到约 80%，确认后再开下一个
  3. 演化式迭代 — 一轮模块做完或方向变了，再规划下一轮（螺旋仅高风险可选）

~80% 指什么

演示 Entry 能开；约定验收点都过；你可以判断这个模块行不行。剩下约 20% 是抛光/边角，列成 Not yet，除非挡演示否则先放下。

模块内部仍可先竖切骨架，再增量堆到 80%。

落地形式缺口（模型不管这个）

缺口要定
Host本机 / Pages / Docker …
Runtime静态 / 本地服务 / 容器
Entry root演示页根路径或 URL
Data / Stack / 网络数据在哪、技术边界、是否仅 localhost

反模式

  • 模块 1 还没确认就做模块 2
  • 一次搭好所有模块的空壳演示
  • 第一个模块死磕 100% 才肯往下（除非你要求）
  • 一口气做完整软件
